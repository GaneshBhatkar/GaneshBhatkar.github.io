ROS 2 Autonomous Mobile Robot Development

Continuous workspace project

This project documents my transition from embedded-systems development toward robotics and autonomous systems engineering. The work was developed progressively inside a single ROS 2 workspace using simulation, sensor data, state estimation, mapping, localization, and navigation.

GitHub Profile Portfolio Repository

1. Project Overview

Instead of developing unrelated ROS 2 demonstrations, I developed the robot system incrementally in one workspace. Each stage builds on the previous stage and adds another capability to the same simulated mobile robot.

ROS 2 Workspace | +-- Mobile Robot Simulation | +-- Robot State Estimation using EKF | +-- 2D LiDAR SLAM | +-- AMCL Localization | +-- Autonomous Navigation using Nav2

Objective

Build a foundation for autonomous mobile robotics using ROS 2 and Gazebo simulation.

Robot Platform

Four-wheel mobile robot developed and tested in a simulated environment.

Development Environment

ROS 2 Humble, Gazebo, RViz2, Python, Linux, and The Construct.

Project Approach

Incremental development, testing, visualization, debugging, and documentation.

2. Technologies Used

ROS 2 Humble Gazebo RViz2 Python URDF TF2 LiDAR IMU Wheel Odometry EKF SLAM Toolbox AMCL Nav2 The Construct Linux

3. ROS 2 Workspace

All stages were developed and tested inside the same ROS 2 workspace. The workspace contains the robot packages, configuration files, launch files, maps, and supporting scripts.

Workspace preparation

source /opt/ros/humble/setup.bash

mkdir -p ~/ros2_ws/src

cd ~/ros2_ws

colcon build

source install/setup.bash

The commands above represent the general workspace workflow. The actual package names and launch files are documented in the project repository.

General workspace workflow

  1. Source the ROS 2 environment.
  2. Navigate to the workspace.
  3. Build the workspace using colcon build.
  4. Source the generated workspace environment.
  5. Launch the required simulation and ROS 2 nodes.
  6. Inspect topics, nodes, services, and transforms.
  7. Test the robot in Gazebo and RViz2.

4. Stage 1 — Mobile Robot Simulation

Completed in simulation

Objective

Create and test a four-wheel mobile robot in Gazebo and understand the basic communication between the robot, ROS 2 nodes, simulated sensors, and RViz2.

Execution process

  1. Source ROS 2 and the project workspace.
  2. Build the workspace.
  3. Launch the Gazebo simulation.
  4. Spawn the mobile robot.
  5. Start RViz2.
  6. Inspect the robot model and TF2 frames.
  7. Send velocity commands to the robot.
  8. Verify robot movement and sensor topics.

Useful inspection commands

ros2 node list

ros2 topic list

ros2 topic info /cmd_vel

ros2 topic echo /cmd_vel

ros2 topic list | grep scan

ros2 topic list | grep imu

Basic system flow

Gazebo | +-- Mobile Robot | +-- Simulated Sensors | | | +-- LiDAR | +-- IMU | +-- Wheel Odometry | +-- ROS 2 Topics | +-- /cmd_vel +-- /scan +-- /imu +-- /odom

5. Stage 2 — Robot State Estimation using EKF

Implemented

Objective

Estimate the robot's position and orientation by combining wheel odometry and IMU measurements using an Extended Kalman Filter.

Input data

Input Purpose
Wheel odometry Provides estimated robot motion from wheel movement.
IMU data Provides inertial measurements such as orientation and angular motion.
EKF configuration Defines which measurements are fused by the filter.

System architecture

Wheel Odometry -----------+ | +----> EKF ----> Filtered Odometry | IMU Data -----------------+

Execution process

  1. Start the mobile robot simulation.
  2. Verify wheel-odometry data.
  3. Verify IMU data.
  4. Load the EKF configuration.
  5. Start the state-estimation node.
  6. Inspect the filtered odometry output.
  7. Visualize the robot pose in RViz2.
  8. Check the relevant TF2 relationships.

Important topics

Topic Purpose
/odom Wheel-odometry information.
/imu/data IMU measurements.
/odometry/filtered Filtered state-estimation output, if used in the implementation.

Result

Sensor-fusion concepts were applied to combine odometry and IMU information for mobile-robot state estimation.

6. Stage 3 — 2D LiDAR SLAM

Implemented

Objective

Generate a two-dimensional occupancy-grid map of the simulated environment using LiDAR data and SLAM Toolbox.

Execution process

  1. Start the mobile robot simulation.
  2. Verify that LiDAR data is being published.
  3. Launch SLAM Toolbox.
  4. Open RViz2 and display the laser scan and map.
  5. Move the robot through the simulated environment.
  6. Observe the map being generated.
  7. Save the completed map.

System architecture

LiDAR Data | v SLAM Toolbox | +----> Robot Pose Estimate | +----> Occupancy-Grid Map | v Saved Map

Map output

The saved map normally contains a map metadata file and an image file. The exact filenames depend on the map-saving command used.

  -f ~/ros2_ws/maps/warehouse_map

7. Stage 4 — AMCL Localization

Implemented

Objective

Localize the simulated mobile robot on a previously generated map using the Map Server, AMCL, LiDAR data, and odometry.

Execution process

  4. Start AMCL.

  6. Set the robot's initial pose.

  8. Observe the localization estimate.

Saved Map -----------+ | LiDAR Data ----------+----> AMCL ----> Robot Localization | Odometry ------------+

Important components

Component Purpose
Map Server Provides the previously saved map.
AMCL Estimates the robot's pose on the known map.
LiDAR Provides range measurements used for localization.

11. Lessons Learned

  • ROS 2 nodes, topics, and message types form the basic communication structure of a robotic system.
  • Correct TF2 frame relationships are essential for robot visualization, mapping, localization, and navigation.
  • Sensor data must be inspected and validated before it is used by higher-level algorithms.
  • State estimation provides a foundation for mapping and autonomous navigation.
  • SLAM and localization are different processes: SLAM creates a map, while AMCL estimates the robot's position on an existing map.
  • Autonomous navigation depends on the correct integration of maps, localization, sensors, costmaps, planners, and controllers.
